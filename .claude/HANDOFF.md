## 3. Что сделано в облачной сессии (0.4.6, betas 5–8)

Подробно — в `CHANGELOG.md` / `CHANGELOG.ru.md` (там же сводка стабильной 0.4.6 в «Не выпущено»).
Коротко:

- **Роуминг**: бесшовный перенос сессии на новый сокет того же транспорта. Без
  автоматического переподключения и смены транспорта — это решение пользователя, не возвращать.
- **Исправления**: SNI по имени сервера, утечка TLS-соединений (HTTP 500 подписок), UDP с
  loopback-сокета, подмена адреса сессии поддельным пакетом.
- **Стабильность 0.4.6**: IDN-домены в исключениях (punycode), исключения по процессам
  (Windows и Linux, режимы прокси и TUN), тайм-аут простоя TCP/TLS 5 минут, API без входа
  не запускается, пустой `api.token` больше не пускает.
- **Десктоп**: одна тёмная тема; убрано «автоподключение» с перебором MTU; стартовый экран;
  *Settings → Server management* (установка и управление своим сервером по SSH).
- **Android**: то же — стартовый экран и Server Management (Flutter + `serversCall` в `ostp-jni`).
- **Сервер**: `ostp manage` (JSON для приложений), `install.sh -y`, файл статистики
  `.ostp_stats.json`, `ostp changelog`/`ostp cl`.
- **Веб-панель**: вёрстка под телефон; адрес через VPN `http://10.1.0.1:<порт>/<путь>/`.
- **Новый крейт `ostp-ssh`**: SSH-клиент (russh + ring), хранилище серверов с шифрованием
  секретов, менеджер, общий для Tauri и JNI.
- **Документация**: README, CONTRIBUTING, SECURITY, `docs/` (en/ru), вики переписаны по коду;
  раздел о принципе Керкгоффса в `docs/*/obfuscation.md`.

## 5. Как собирать и проверять локально

| Что | Команда |
|---|---|
| Всё на Rust | `cargo test --workspace` |
| Шаблоны веб-серверов, CLI, changelog | `cargo test -p ostp --bin ostp` |
| JNI-экспорты | `cargo test -p ostp-jni` |
| GUI (Tauri) | `cd ostp-gui; npm install; npm run dev` (сборка: `npm run build:installer`) |
| JS интерфейса | `node --check ostp-gui/src/main.js; node --check ostp-gui/src/servers.js` |
| Flutter | `D:\Toolz\flutter\bin\flutter analyze lib` и `flutter test test/servers_ui_test.dart` в `ostp-flutter` |
| SSH против настоящего sshd | только Linux под root (WSL подойдёт): `sudo cargo test -p ostp-ssh --test sshd -- --ignored --test-threads=1`, для теста менеджера ещё `OSTP_BIN=target/debug/ostp`. Тест создаёт пользователя `ostpsshtest` и пишет в `/etc/ostp` — только на одноразовой машине |
| aws-lc не подтянулся | `cargo tree -i aws-lc-sys` в корне и в `ostp-gui/src-tauri` — должно быть пусто |

Workspace не отформатирован целиком `rustfmt` (больше тысячи расхождений): форматируй только свои новые файлы.

## 6. Правила проекта (что соблюдала облачная сессия)

- **Ветки**: `alpha → beta → master`, только fast-forward. Выпуск — `scripts/gha.ps1`
  (итерации в `.release-state.json`, номер сборки Android в `ostp-flutter/pubspec.yaml`,
  заголовок версии в оба CHANGELOG).
- **CHANGELOG**: каждое изменение — в «Не выпущено» обоих файлов (en и ru); тест проверяет,
  что версии в них совпадают.
- **Документация** всегда на двух языках с одинаковым содержанием (`docs/en`, `docs/ru`,
  README, CONTRIBUTING, SECURITY). Писать честно, по коду, без обещаний сверх сделанного.
- **Параллельные чаты**: перед работой свериться с `.claude/COORDINATION.md` на всех ветках,
  занять файлы строкой в таблице, освободить после слияния.
- **Совместимость**: 0.4.6 совместима по протоколу с 0.4.5 (PROTOCOL_VERSION 5). Всё, что
  ломает протокол, — только в `claude/protocol-v6` / 0.5.0.
- **Пожелания пользователя**: отвечать по-русски; в конце работы коммит и пуш; никакого
  автоматического переподключения или смены транспорта в клиенте — выбирает пользователь;
  в десктопе одна тёмная тема и две кнопки сверху (пробер и настройки).

## 7. Если что-то не сходится

- `git pull --ff-only` отказывает — локальная `alpha` разошлась с репо. Не делай `reset --hard`,
  пока не посмотришь `git log origin/alpha..alpha`: там могут быть твои коммиты.
- Сборка GUI ругается на `Cargo.lock` в `ostp-gui/src-tauri` — это отдельный Cargo-проект со
  своим lock-файлом; `cargo update -p ostp-ssh` в `ostp-gui/src-tauri` его подтянет.
- Полная история облачной сессии — только в самом чате; всё, что имеет значение для кода,
  есть в коммитах, CHANGELOG и этом файле.
